# RetailMind AI — Day 1: End-to-End ML Pipeline & ML-as-a-Service

RetailMind AI is an incremental, end-to-end retail intelligence platform. Each daily increment adds a production-minded capability to the same codebase. **Day 1 establishes the ML backbone** with a persisted customer-churn prediction pipeline.

## Day 1 deliverable

- Load and inspect the Telco Customer Churn dataset.
- Split data into stratified training and test sets.
- Preprocess numeric and categorical features in a single scikit-learn pipeline.
- Train a baseline Logistic Regression classifier.
- Evaluate accuracy, precision, recall, and ROC-AUC.
- Persist the complete fitted pipeline with `joblib`.
- Expose a small Python prediction helper in `src/service.py`.


The script prints the dataset shape, target balance, missing-value summary, and test metrics. It saves the complete preprocessing + classifier pipeline to `models/churn_pipeline.joblib` and writes the metrics to `models/metrics.json`.

## Dataset and target

Dataset: IBM Telco Customer Churn (Kaggle: `blastchar/telco-customer-churn`).

Target column: `Churn` (`Yes` / `No`). `customerID` is an identifier and is excluded from model features. `TotalCharges` is converted to numeric; blank strings are treated as missing and imputed inside the pipeline.

## Day 1 baseline

Run `python -m src.train` on the included CSV to generate the actual metrics for this environment. The script writes them to `models/metrics.json`. The baseline should be treated as the comparison point for future RetailMind increments. Do not compare metrics across different train/test splits or preprocessing changes without documenting them.

## Notes

- The train/test split is stratified and uses a fixed random seed for repeatability.
- All preprocessing is fitted only on the training partition because it is inside the scikit-learn pipeline.
- `models/` is retained in Git so the Day 1 model artifact can be versioned; for larger future models, consider Git LFS or model storage.
- This is a learning/demo baseline, not a production deployment or a substitute for business validation.

## Day 3 — Multi-Model Comparison, Tuning & Bias-Variance

### Objective
Tune competing churn prediction models using GridSearchCV and
stratified cross-validation. Select a champion based primarily on
validation recall for the positive churn class (`Yes`).

### Models evaluated

- Logistic Regression
- Decision Tree
- Random Forest
- Support Vector Machine (SVM)

### Methodology

- Train-test split: 80/20, stratified
- Cross-validation: StratifiedKFold, 3 folds
- Hyperparameter tuning: GridSearchCV
- Primary selection metric: Recall
- Additional metrics: ROC-AUC and Accuracy
- Bias-variance diagnosis: Training recall vs validation recall
- Learning curves: Training and validation recall against training size

### Holdout evaluation

The selected champion is evaluated on the untouched test set.
Its accuracy, precision, recall and ROC-AUC are saved in
`models/day3_tuning_results.json`.

### Bias-Variance interpretation

- High training recall and low validation recall: possible overfitting.
- Low training and validation recall: possible underfitting.
- Similar, high training and validation recall: better generalisation.
- Learning curves help indicate whether more training data may improve performance.
